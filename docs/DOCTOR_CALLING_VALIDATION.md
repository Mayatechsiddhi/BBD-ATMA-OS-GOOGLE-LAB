## Failures corrected during implementation

- Initial Prisma generation rejected the optional appointment relation without matching composite uniqueness. The schema/SQL relationship was corrected, then cancelled-history behavior was improved using a subsequent additive migration and a one-to-many relation with partial active uniqueness. The successful eight-migration chain includes both steps; applied SQL/history was not rewritten/reset.
- Reception streams explicitly require staff read access rather than merely display access, preventing a demoted DISPLAY account from retaining a live staff screen. Current staff role changes trigger reception refresh. Display streams still emit no patient data.
- Initial formatting/lint checks caught new-file formatting and unescaped JSX apostrophes; corrected without disabling checks.
- A partial early validation ran 52 integration cases successfully; two later cases and a reissuance case expanded the final total to 55. The obsolete HTTP/browser attempt was stopped before the lifecycle correction; it is not counted as a completed full suite.
- The display-invitation regression initially failed because INSERT RETURNING requested audit-row SELECT. The shared audit helper now uses createMany to append without returning private data, preserving DISPLAY read denial. Full clean security/integration reruns passed; no audit read permission was broadened.
