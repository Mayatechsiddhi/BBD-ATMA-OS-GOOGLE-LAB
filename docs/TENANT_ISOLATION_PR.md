The foundation used a PostgreSQL superuser for application queries and had no RLS on tenant data. Existing scoped services passed their tests, but an omitted ORM predicate could expose another organization's records, and privileged fixture connections could conceal that gap.

This change requires a separate non-owner/non-bypass runtime connection, adds FORCE RLS to Organization/Membership/Invitation/AuditEvent/Contact, and binds actor/tenant/invitation context to one Prisma transaction and its PostgreSQL transaction ID. Policies recheck membership and permissions, restrict invitation bootstrap, and prevent foreign writes. Runtime audit records are append-only; direct global user deletion and unused destructive operations are not granted. Narrow, fixed-search-path definer functions handle organization bootstrap and membership-policy recursion. The migration owner remains explicitly trusted and cannot be used by the app.

Keeps service checks, advisory locks, auth/session behavior and the original migrations. Moves fixture inspection/cleanup to a local-only admin client so actual auth/services exercise the restricted app role. Fixes the existing WASM migration adapter's semicolon splitting to support complete PostgreSQL function scripts and rollback. Adds role/grant checks at startup, health and transaction boundaries, targeted AGENTS.md guidance, audit/threat-model documentation and local/CI migration validation. No dependencies or product features added.
