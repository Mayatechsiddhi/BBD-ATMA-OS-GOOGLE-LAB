# Workforce harness security hardening

Base: fef8dcca13f1be48f1045e3aed2eefec30339211. Branch: security/workforce-harness-hardening. Original BBD code only; no dependencies, database models, grants, migrations, customer features or provider connections added.

## Corrections

- W1: normal audit capacity remains fail-closed for submit, approve, reject, execute, retry and resume. Emergency pause and irreversible revocation can append to a separate overflow ledger without deleting normal evidence. A shared monotonic sequence orders both ledgers for department-filtered reads. Overflow storage is bounded by maxTasks + 1: each retained task can be revoked once, and only one overflow pause can occur because resume requires normal capacity. Total events are at most maxAudit + maxTasks + 1. Same-state pause and failed commands add no audit entries. Copies remain isolated. There is no reset, pruning or bypass-resume command. Recovery is inspect/export through the authorized in-memory audit read; restoring execution requires a separately reviewed durable recovery controller. Restart is not a safe receipt-preserving recovery strategy.
- W4: tests now actually enter RETRYABLE_FAILURE and attempt retry after expiry and during pause. They assert unchanged attempts/state and successful explicit retry only after an audited resume.
- W5: all ten public methods count runtime-allowlisted WorkforceError/Zod denials using fixed method/reason labels and saturating numeric counters, independently of the event ledger. No actor/task/company selectors, input, exception message, Zod issue, credentials or timestamps are retained. At most 100 method/reason buckets (nine WorkforceError codes plus INVALID_INPUT). Only an approver assigned both departments may read company-wide aggregate counters; other readers deny. Returned arrays cannot mutate counters. Telemetry is neither a durable security audit nor denial identity attribution, and runtime/unexpected exceptions are not classified as authorization denials.
- Import boundary: ESLint rejects mock imports from application source. An existing-unit-suite architectural check resolves every non-generated src module edge with TypeScript, including aliases, relative imports, barrel exports, require, import-equals, import types and dynamic imports; computed loading is rejected. All src outside the mock directory is covered, preventing an intermediary service from bridging the boundary. This is CI/static enforcement, not a Node sandbox or protection against arbitrary code execution.
- W6: the existing HTTP runner emits dispatch, headers and failure stages with request sequence, method, allowlisted/redacted route template, elapsed time and HTTP status or closed failure category. No URL query, body, cookies, headers, response content or raw exception is logged. The original exception propagates. Existing GET 60s and POST 20s deadlines, redirects and security assertions are unchanged. Text/JSON consumption emits separate body start/end/failure stages without logging contents or changing consumption. Diagnostics are correlation evidence, not a timeout fix.

## Explicit production blockers (W2/W3)

No authenticated workforce endpoint or production controller exists. Trusted constructor principal IDs are not real authentication. Process-local approvals, revocations, pause state, receipts and telemetry disappear at restart and do not coordinate multiple instances. Real authenticated identities, durable scoped policy, approval/revocation, execution receipts and atomic multi-instance claims belong in the subsequent workforce control-plane sprint. No real adapter or customer data may be connected until that design and human security review pass.
